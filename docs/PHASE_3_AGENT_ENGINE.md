# Phase 3 — Core Multi-Agent Dispute Investigation Engine

## Objective
Phase 3 implemented the core collaborative Multi-Agent Dispute Investigation Engine for Resolve-AI using **LangGraph**, **FastAPI**, **Pydantic**, and **SQLAlchemy**. The engine orchestrates 7 specialized agents across structured investigation states, enforces deterministic governance rules, executes mock enterprise transactions, and exposes human-in-the-loop approval APIs.

---

## 1. Multi-Agent Workflow Architecture

```
                       [Dispute Case Intake]
                                 │
                                 ▼
                     [Case Coordinator Agent]
            (Generates Investigation Plan & Tasks)
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
[Evidence Agent]         [Policy RAG Agent]      [Fraud Risk Agent]
(OCR/Vision analysis)    (Policy compliance)     (Multi-signal heuristics)
         │                       │                       │
         └───────────────────────┼───────────────────────┘
                                 │
                                 ▼
                    [Resolution Strategy Agent]
              (Synthesizes Options & Selection)
                                 │
                                 ▼
                  [Deterministic Risk Engine]
  (Evaluates fraud_score, confidence, value, and eligibility)
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
            [LOW RISK]                      [HIGH RISK]
                 │                               │
                 ▼                               ▼
    [Workflow Execution Agent]           [Escalation Agent]
  (Calls Mock Enterprise APIs)      (Moves to HUMAN_REVIEW)
                 │                               │
                 │                      [Admin / Manager Approve]
                 │                               │
                 └───────────────┬───────────────┘
                                 │
                                 ▼
                    [Persist Trace & Audit Log]
                                 │
                                 ▼
                  [Explainable Decision Passport]
```

## 2. Shared Workflow State (`ComplaintState`)
Located in `apps/ai_engine/graph/state.py`:
- `investigation_plan`: Dict generated by Coordinator Agent.
- `evidence_result`: Structured evidence confidence, damage findings, OCR items.
- `policy_result`: Policy ID (`WARRANTY-4.2`, `REFUND-2.1`, `AUDIT-8.1`), name, allowed actions, eligibility notes.
- `fraud_result`: Multi-signal risk score (0.0 to 1.0), risk level (`LOW`, `MEDIUM`, `HIGH`), signal breakdown.
- `resolution_result`: Candidate options array, selected `recommended_action`, confidence, rationale.
- `escalation_result`: Escalation reason, priority, recommended reviewer (`fraud_specialist`, `resolution_manager`).
- `execution_result`: Executed mock API receipts, transaction IDs, waybill tracking numbers.
- `agent_trace`: Timeline array containing execution duration, confidence, and log details.

## 3. Specialized Agents Implemented
1. **Case Coordinator Agent** (`apps/ai_engine/agents/coordinator/agent.py`): Builds 6-task investigation plan and sets priority.
2. **Evidence Verification Agent** (`apps/ai_engine/agents/evidence/agent.py`): Performs OCR & Vision damage detection heuristics.
3. **Policy Intelligence Agent** (`apps/ai_engine/agents/policy/agent.py`): Matches corporate coverage clauses and generates policy references.
4. **Fraud Detection Agent** (`apps/ai_engine/agents/fraud/agent.py`): Computes multi-signal risk scoring using non-accusatory terminology.
5. **Resolution Strategy Agent** (`apps/ai_engine/agents/resolution/agent.py`): Evaluates candidate options (Replacement, Refund, Partial Refund) and selects optimal recommendation.
6. **Escalation Agent** (`apps/ai_engine/agents/escalation/agent.py`): Halts automated execution for high-risk / audit cases and routes to human review queue.
7. **Workflow Execution Agent** (`apps/ai_engine/agents/workflow/agent.py`): Invokes Mock Enterprise APIs to execute approved replacements and refunds.

---

## 4. Deterministic Risk Engine (`apps/ai_engine/graph/routing.py`)
Centralized configurable thresholds:
- `FRAUD_ESCALATION_THRESHOLD = 0.60`
- `LOW_CONFIDENCE_THRESHOLD = 0.80`
- `HIGH_VALUE_THRESHOLD = 50000.0`

Auto-approval occurs **ONLY** when:
`fraud_score < 0.60 AND evidence_confidence >= 0.80 AND resolution_confidence >= 0.80 AND policy_eligible == 'Eligible' AND claim_amount < 50000.0`.
Otherwise, the engine routes to **`escalation`** (`Requires_Review`).

## 6. REST API Endpoints Added
- `POST /api/v1/cases/{id}/investigate`: Triggers LangGraph multi-agent workflow.
- `GET /api/v1/cases/{id}/trace`: Returns step-by-step execution timeline.
- `GET /api/v1/cases/{id}/decision`: Returns Explainable AI Decision Passport.
- `POST /api/v1/cases/{id}/approve`: Human-in-the-loop approval endpoint (resumes execution via Mock Enterprise APIs).
- `POST /api/v1/cases/{id}/reject`: Human-in-the-loop rejection endpoint.

  - Result: Fraud score `0.99` (High Risk), Policy `Ineligible - Audit Required`.
  - Outcome: **Halted for Human Review** (`Requires_Review`). Admin calling `/approve` resumes execution and processes refund.
